# Codex app-server 验收宿主

此宿主运行真实 Codex app-server，并将 VibePaper 的 MCP form 请求交给当前会话中的用户决定。只有用户明确答复后，控制器才向原请求返回 `accept`；超时、关闭、未知请求和不匹配的请求 ID 均不批准。它是验收用 relay，不能作为 Codex 桌面原生 MCP 弹窗已完成视觉验收的证据。

首次真实 `--configuration-only --app-server-host` 在模型回合开始前停止：`CODEX_APP_SERVER_MCP_SCOPE_INVALID`。原始记录保留在 [运行记录](codex-agnes-acceptance-2026-10-17T12-24-20-113Z.json)，未配置模型、未提交媒体任务，退出前清除凭据、撤销测试授权并完成明文扫描。

本机 Codex 0.154.0 的配置表覆盖采用深度合并，单独设置 `mcp_servers.vibepaper` 不会移除继承服务。宿主要求只暴露本次 VibePaper 服务；不能通过放松范围校验来忽略其他服务。修正后须重新做真实配置及媒体链路验收。

10-18 修正使用 Python 3.11+ 标准库 `tomllib` 解析既有配置，只在内存提取服务名称；配置通过 stdin 传入，解析子进程不接收模型凭据环境变量，不输出值或原始错误正文。禁用覆盖仅作用于本轮 Codex 子进程，不修改用户配置文件。此依赖只用于验收宿主，桌面 MCP 桥接不依赖该解析步骤。

真实客户端还会启动内置 Apps；仅禁用配置中的 MCP 和插件不足以隔离。新增本轮 `features.apps=false` 后，实际状态确认一个 VibePaper 连接、四个禁用条目、其他条目工具数为零，无分页。此前范围失败记录继续保留。后续模型回合在 MCP 工具调用前失败：[脱敏分类](codex-agnes-acceptance-2026-10-18T11-19-23-828Z.json)为模型不支持，零媒体任务；此结果不作为生成通过。QA 宿主现显式查询同一客户端 `model/list` 的唯一可见默认模型，只用于本次临时线程，不更换提供方、不改用户日常设置，目录缺失、歧义或分页时停止。

[16 项宿主检查](codex-app-server-host-tests-20261018.json)由主审独立通过；它们不运行真实模型或供应商。实际回合与完整媒体结果另外记录，不能以本地 fake app-server 测试替代。
