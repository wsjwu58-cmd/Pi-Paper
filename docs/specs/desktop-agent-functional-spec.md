# VibePaper 桌面本地版 Agent 功能规格

## 2026-10-03 模型输出截断

原 TS runtime 对输出上限导致的 `length` 回复进行有限续跑，保留已执行工具的结果；待确认或用户停止时不得派发续跑。超过续跑次数或整体超时则结束 Run，原面板持久显示具体原因，不只弹临时通用错误。连接中断单独标记，不误提示为 Key 配置错误。历史恢复只展示状态，不重放旧失败回合。边界及证据见 [截断修复记录](../plans/2026-10-03-agent-output-limit-validation.md)。

## 2026-10-02 持久计划执行

计划执行通过原 API 本地适配、Preload/Main、Worker 和原 TypeScript 协调器连接。显式执行后按依赖推进，生成与删除继续使用原确认卡；确认、Run、步骤与整批任务持久关联。任务输出全部核验后才执行下游；停止和恢复先查本地权威状态。控制库 v8 及执行接口、恢复边界和测试证据见 [计划执行记录](../plans/2026-10-02-agent-plan-execution-validation.md)。此前 v7 只有计划仓储的描述保留为阶段记录；此更新也不代表全部 Agent 1:1 总验收完成。

## 1. 产品边界

桌面版是**单用户、本地项目文件优先的创作工具**。画布、节点、连线、素材原件和生成结果、生成任务、Agent 会话、工具记录、Skill、记忆、设置、运行日志和备份都由本机持有；不要求注册、登录或连接平台服务器才能打开项目、继续会话及使用已安装的本地模型。Agent 不能因为无网络自动退回云端 Agent、云端存储或云端生成。

首版同时支持本机模型和用户配置 API Key 的云端模型。默认模式为“本地处理”：只调用本机模型/生成器，项目数据不作为遥测、同步或模型请求发送到外部地址。第三方 API 是用户**显式启用的独立联网模式**：在启用前说明供应商、将发送的数据类型、供应商可能收取的费用、隐私边界；每次使用按设置显示明确的联网标识。联网模式可以把结果保存回本地，但不能再宣称“数据仅在本地处理”。不把可联网等同于引入平台账户、点数或云端会话存储。

Agent 面板以原 `vibepaper-web/src/features/canvas/AgentPanel.tsx` 为前端迁移源码，直接在原组件及其事件归约、消息时间线和输入交互代码上改造桌面适配；不以另写 `DesktopAgentPanel` 替代。通过显式本地会话/API/SSE（或等价 IPC 事件）和画布状态适配接入桌面 Worker，并保持 Web 默认调用路径不变。面板与原版 Web 的可见布局和交互保持 1:1；本专项增加的是运行层上下文压缩、短期记忆、长期记忆与本地恢复。云端普通消息在配置页完成披露后，由用户主动选择提供方并点击发送直接执行，不弹逐次 API 确认。Agnes 是当前测试提供方，不是唯一或最终供应商；模型选择应由 Provider Registry 驱动。完整 UI 对照见 [桌面 UI 保真清单](desktop-ui-parity.md)。

Agent 工具 schema、画布命令和角色提示词以原 `pi-main/packages/vibepaper-agent-service` TypeScript 实现为唯一源代码；桌面版在其上接本地适配器和桌面策略。验收要确认实际 Worker 调用的是原运行入口及原工具定义，而非只复制界面或维护一份功能相似的桌面工具实现。

桌面版不包含平台点数、冻结/结算/充值、订阅套餐、签到奖励、邀请返利、企业配额、运营审核、共享云端记忆或远程 Agent 服务。Token 用量可继续统计，但只作为本机资源/模型调用信息，不能叫“点数”或“余额”。非 Agent 模块和整体产品导航按全服务方案处理；创意广场源码保留但入口关闭。不迁移旧 Web 数据，也不删除旧代码或旧用户数据。

## 3. Agent 对话与创作行为

1. 当前项目、画布和用户选中节点由桌面宿主显式交给 Agent；每条引用带稳定节点标识和画布版本。Agent 不根据画布空间位置猜测创作依赖。
2. Agent 通过工具白名单读画布/素材/模型能力，通过 Tool Gateway 写入；不能直接改画布 JSON、SQLite 表或本地文件来绕过领域校验。节点能力、输入角色、模型 `inputMode`、参考图上限和顺序在执行前校验。
3. 用户明确要求一对一时，按目标逐项声明唯一来源；三个分镜对应三个视频时生成三条语义正确的连线，不做 3×3 笛卡尔积。来源、首帧/尾帧角色或排列不明确时，先提问，再创建/删除相关节点。
4. 本地生成任务可异步运行。Agent 只在本地 TaskStore 标记成功且结果文件可读取后宣布完成；本地模型缺失、资源不足或失败时显示具体状态，不静默启用外部 API。
5. Agent 提交生成沿用原版系统确认：单个目标由 `submit_generation` 提出确认，多个独立目标由 `submit_generation_batch` 提出一次批量确认；确认后才向本地 TaskStore 提交。确认展示目标、模型、输入与覆盖影响，去掉预计点数、冻结和结算；拒绝、过期或画布版本变化后不得执行。删除/覆盖不可撤销内容也须可撤销或显式确认，清空画布和批量写入超阈值先确认。启用联网模型时，在模型配置处披露数据范围和供应商可能收取的费用；用户主动选择云端模型并点击发送即完成普通 API 调用的数据发送授权，不另弹逐次发送确认。新增媒体上传等更宽范围需重新披露和授权。
6. 面向用户的回复只说创作对象、结果和待办，不暴露内部节点 ID、工具名、账本键或存储路径。取消、关闭面板和重启后可从本地会话与任务状态恢复。

当前已接通的工具切片（不代表 Agent 迁移完成）：`get_canvas_summary`、`get_node_detail`、`check_task_status`、`list_models` 经 Main → Local Core 读取；`create_nodes`、`connect_nodes`、`update_node_config`、`layout_nodes` 经白名单 RPC 写入本地画布。创建节点支持 1–20 个目标及逐目标 `sourceNodeIds`，连接按 `nodeIds` 顺序只连相邻节点；节点配置更新沿用旧工具的配置字段/参数回退规则。布局按旧版完整画布节点顺序计算位置，支持 `direction`、`gap` 和逐节点显式 `positions`，保存时保留连线、编组与堆叠，并按旧画布版本做整图 CAS。乐观锁版本由运行时推进；创建、连线和布局使用由工具调用及请求参数派生的稳定幂等键，节点配置更新使用稳定工具调用键。创建和连线为多个本地命令顺序执行，部分失败会回报已完成步骤和可能已修改画布，不会伪报整批成功。生成动作沿用持久化确认后提交本地任务。当前面板已把用户选中节点作为受限参考元数据传给 Agent；逐目标连线仍须明确声明来源关系。内置及项目 Skill 的列表、编辑、导入和加载已接原面板与原 Pi loader；历史消息中的 Skill 卡片、短期/长期记忆与上下文压缩仍有缺口。原 Pi runtime 未提供结构化短剧资产或生产批次工具，因此它们不属于 1:1 缺口；如需自然语言操作，应另行扩展。聚焦测试已覆盖上述部分路径，但 Agnes 真实模型的工具调用和短剧批次云端执行尚未端到端验证，因此不构成 Agent 1:1 验收。

### 2026-09-29 Agent 面板短剧与用量实现状态

桌面 `AgentPanel` 直接复用原 `DramaAssetsTab`、`DramaProductionPanel`、审校面板和 `UsageTab`，经 `api()` 的显式桌面适配调用本地 bridge。短剧资产页可列出并新建/更新九类结构化资产（故事圣经、剧集、场景、角色档案、角色 Look、镜头规格、连续性约束、音频提示和字幕）；筛选支持资产类型、剧集、场景与镜头。资产保存沿用 schema v14 的 `drama_assets` 与 `drama_asset_commands`，支持版本冲突、类型不可变、版本递增和幂等结果快照；升级前创建回滚副本。

短剧系列、角色、角色参考包、镜头、关键帧及渲染血缘已写入本地项目 SQLite schema v16。Local Core 按项目和画布隔离数据，并校验角色系列归属及当前 Look revision、原有镜头规格与 2–5 秒时长、接受关键帧时的唯一已批准参考包。视频节点只读取同镜头且参考包仍匹配的已接受关键帧；渲染血缘必须指向同镜头关键帧，角色失效只更新该角色绑定的血缘。原短剧 API 已由 Renderer API adapter、Preload、Main IPC、Local Core 和 ProjectStore 串接，领域写入与结果快照在同一 SQLite 事务提交；幂等重放返回原结果，重启后保留接受状态。关键帧和视频节点创建仍通过画布版本 CAS 与命令幂等记录。

生产批次与任务确认状态使用 schema v17。原 `DramaProductionPanel` 已接候选查询、幂等批次创建、展示目标/提供方/模型/提示词/关键帧输入的显式确认、逐镜头 TaskStore 提交、失败码同步和逐 job 局部重跑确认。ProjectStore 校验批次镜头、视频节点、已接受关键帧及成功图片任务输出；确认绑定批次、画布版本、内容哈希和有效期。TaskStore 提交使用稳定幂等键，批次读取可在任务已创建但关联未完成时找回任务并校验成功输出文件。界面显示不可用原因并排除不可用镜头；Agnes 和 Ark 都拒绝短于 4 秒的批次目标，Ark 本地视频/音频参考因缺少供应商上传链仍不可用。批次确认明确说明提示词和已接受关键帧会发送给所选云端提供方并可能产生费用，不显示平台点数。

`/render-reviews` 的 `continuity-v1` 规则审校读写已接本地存储，运行 `SHOT_DURATION`、`CHARACTER_CONTINUITY` 和 `AUDIO_VIDEO_SYNC` 规则，并保存 findings、证据、建议、重试次数及可关联的本地视频任务。没有本地视频任务时，报告仅基于请求提供的测量值；自动媒体分析器仍未实现。用量页从 Pi 会话 JSONL 读取实际 `usage`，按 entry ID 去重，展示 Token 总量、缓存 Token、模型/工具调用总数和按模型拆分；本地响应不含平台点数或费用，输入/输出 Token 暂未单独展示。一次 Windows 开发窗口中的 Agnes 对话后，用量页显示了非零实际 Token 和调用数。该记录仅证明单次会话链路，仍需逐项核对 JSONL 数值并验收重启恢复。

桌面 Agent 的原 `request_render_audit` 工具现经 Worker、原 TS Local Tool Gateway 和 Main 白名单调用本地 `render-reviews:create`。Main 根据权威画布节点选择原通用或竖屏短剧 profile；审校工具只在短剧 profile 中可见。网关只回传规则结论、findings 和规则版本，模型不能自行写入规则结果；提交前检查当前项目、画布版本及目标节点。Main 将画布版本传给 Local Core，ProjectStore 在同一串行 enqueue 中按 SQLite 权威版本执行可选 CAS、复核目标并写入报告，消除 Agent 版本检查与写入之间的两次 RPC 窗口；原 Renderer 审校调用不传版本时保持旧行为。原 Pi runtime 不含结构化短剧资产或生产批次工具，这些自然语言操作若需要应另行扩展，不列为 1:1 前置。

桌面与 Web 共享原面板组件并通过本地 API/bridge 适配；Store、Renderer API 和面板定向测试覆盖幂等、拒绝确认、TaskStore 关联恢复、失败协调、重跑 attempt 递增和活动任务轮询。真实 Agnes/Ark 批次请求、桌面应用中的完整中断恢复、同状态截图与逐操作录屏仍未验收。自动化测试和原组件复用都不能单独证明 UI 1:1；审校媒体实测能力仍是缺口。原 Pi runtime 不含结构化资产或生产批次工具；若需自然语言操作，应作为额外能力另行扩展，不列为 1:1 验收项。

## 4. 数据与记忆功能

### 2026-09-30 项目记忆与压缩存储切片

原 Pi TypeScript `desktop/project-memory.ts` 以原 `MemoryService` 接入项目内 `agent/memory/MEMORY.md`。桌面 Worker 打开项目时初始化，后续回合把有长度上限的有效偏好注入原 `runDramaTurn.memoryContext`；读取工具始终可用，保存、编辑和删除工具只在本轮用户明确要求对应操作时注册，执行时再验证意图。普通“保存画布”不会授权写记忆。写入沿用原服务去重、检索及软删除，串行执行，拒绝明显的凭据内容；文件按原子替换写入。原 Web 路径不启用这些桌面工具，审校只读 profile 只允许读取。项目备份支持当前控制库 v1–v3，恢复副本将这些偏好的项目身份重绑，失效待处理及已接受的旧确认。

原 `DesktopAgentSessionStore.appendCompaction` 已能追加调用方提供真实摘要的 Pi compaction entry，保留完整工具调用/结果尾部，拒绝占位摘要和未配对工具历史；JSONL 原消息不删除。可选检查点可从 JSONL 重建，缓存损坏不阻断恢复。Worker 已将恢复出的真实摘要交给原 TS runtime，历史展示读取完整活动分支原文。52 条历史及检查点缺失/损坏的重启测试已通过。

这仍是阶段实现：Worker 尚未自动生成覆盖历史的摘要或调用 `appendCompaction`，全请求预算、完整用户轮次切分、会话工作状态投影、session/global/daily 记忆、候选审阅、记忆管理 UI 和真实模型跨压缩回合仍未验收。项目记忆目前注入有界的已保存偏好，按需检索由读取工具完成。2026-09-30 的 Agent 定向测试 32/32、桌面测试 180/180、原 TS 构建和 Worker 构建启动检查通过；这些测试不代表 Agent 1:1 完成。

| 数据 | 保存位置与生命周期 | 用户能力 |
| --- | --- | --- |
| 完整对话、Pi 工具调用/结果 | 项目内 JSONL，压缩不删除原文 | 查看、继续、导出、删除会话 |
| 用户消息的参考卡片元数据 | 同一 Pi JSONL 中的自定义条目，以原始消息条目 ID 关联；每条最多 8 个节点，只保存卡片所需的节点标识、类型、标题、状态和受限的本地 `vibe://app/...` 预览标识 | 重启后恢复节点参考卡片；不保存节点提示词、文本正文或带签名参数的云端预览 URL。当前也持久化所选 Skill 标识，但历史消息界面尚未渲染 Skill 卡片，此项仍是 UI 保真缺口 |
| Run、确认、幂等、任务关联 | 项目内 SQLite；本地业务状态仍由各自存储负责 | 查看进行中/失败任务，安全重试 |
| 压缩摘要和会话工作状态 | JSONL compaction 记录 + 可重建检查点 | 重启后继续；必要时重新读取原始事实 |
| 会话记忆 | 项目内 `session-memory/<id>/memory.md` | 查看当前会话连续性信息 |
| 项目/画布偏好 | 项目内 `memory/*.md` | 查看、编辑、删除、导出 |
| 全局用户偏好 | 本机用户数据目录 `memory/*.md` | 查看、编辑、删除；不自动同步其他设备 |
| 当日临时记忆 | 本地文件或 SQLite，按明确到期时间清理 | 查看或清除 |

显式“记住/以后默认”可写入非敏感长期偏好；从普通对话推断的习惯先作为候选，不自动成为事实。画布节点是否存在、任务是否成功等只从本地权威业务存储核验，不能靠记忆或摘要决定。记忆文件属于低信任资料，不可覆盖当前用户指令、系统规则或工具权限。存储密钥时使用操作系统凭据能力，不写普通 Markdown/JSONL；会话导出前提示其中可能含提示词、素材信息和工具结果。

## 5. 上下文压缩与断点恢复

每次调用模型前，以完整上下文窗口扣除 system、工具、Skill、当前用户请求、记忆、输出预留和安全余量，再给历史分配预算。大工具结果先落盘并留下可回查引用，旧结果再转短占位；仍超预算时仅在完整轮次边界摘要旧历史，保留近期工具调用与结果配对。压缩仅改变模型输入视图，不裁剪原始 JSONL。

断点恢复读取上次有效 compaction、之后的完整轮次和本地任务状态。用户消息的参考卡片元数据通过稳定的 Pi 消息条目 ID 与消息关联，在会话历史装载时恢复；它与 Agent 提示词和自然语言回复分开保存。写画布/提交生成前先写持久化操作意图与幂等键；崩溃后先核验本地业务结果，不能重放已成功工具。离线是默认可运行状态；若本地模型未安装则显示安装/配置缺失，而不是切换云端。项目目录移动后通过稳定项目标识恢复会话，不依赖绝对路径作为身份。

## 6. 验收条件

- 无账户、无网络、无 PostgreSQL/Redis/Nacos/Docker 的桌面环境中，可打开项目和历史会话；本地模型及生成器已安装时能完成创作。缺少本地模型时明确报缺失，不上传内容。
- 创建文本分镜后经历至少 50 条消息、一次压缩和一次进程重启，Agent 仍能定位正确分镜与画布版本；工具原文可从本地日志找回。
- 发送带有节点引用的消息后重启，历史消息仍显示同一组节点卡片；本地 JSONL 不因卡片恢复而额外保存节点提示词/正文或带签名的云端预览 URL。
- 三个分镜各创建一个视频节点，形成 1:1 连线；输入关系不明确时先问用户，不先删除旧节点或写错误连线。
- 对工具成功但会话落盘中断、任务已创建但响应丢失、JSONL 尾行损坏和项目搬迁进行恢复测试；不会重复创建节点或生成任务。
- UI、Agent 回复和本地任务状态不出现平台点数、余额、充值、签到、套餐、企业配额；Token 用量若展示，明确与本机/第三方模型调用有关。
- 检查默认本地模式的网络出口：没有会话、素材、提示词、日志、遥测或模型请求离开本机。首版云端模式单独验收供应商/发送范围告知、用户授权、Key 安全存储和断网/Key 无效错误。
