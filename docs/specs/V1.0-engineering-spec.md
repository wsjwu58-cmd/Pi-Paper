## 1. 问题与目标

### 1.1 要解决的问题

多模态内容生产链路分散（文本工具、生图/生视频、剪辑、素材管理割裂），缺少统一画布容器、上下游引用可视化、Agent 编排与企业级点数/权限管理。

### 1.2 产品目标

在同一无限画布内完成「创意 → 生成 → 编辑 → 组合 → 导出」，支持个人付费与企业点数分配。

### 1.3 V1.0 成功判据（可测）

| 判据 | 度量 |
|------|------|
| 创作闭环 | 新用户可完成：注册 → 建画布 → 生成至少一类内容 → 保存/下载 |
| 计费正确 | 冻结/结算/超时解冻/失败解冻无重复扣费；流水可按 `task_id` 追溯 |
| 任务成功率 | `task_generate_success / task_generate_submit` ≥ 95%（剔除用户主动取消） |
| Agent 可控 | 凡 §5.2.1 需确认操作，未确认前不得改画布或扣费 |
| 性能底线 | 常规画布 50–60 FPS；非生成 API P95 ≤ 1s；首屏可交互 ≤ 3s |

## 3. 系统架构 Spec

### 3.1 逻辑架构

```
vibepaper-web (React)
        │ REST / SSE
        ▼
vibepaper-gateway (鉴权 · 限流 · 路由)
        │
   ┌────┴────────────────────────────────┐
   │ Java 业务服务                        │ Python AI 服务
   │ identity · canvas · asset · billing │ generation · agent
   │ enterprise · gallery · admin        │ (+ Celery workers)
   └────┬────────────────────────────────┘
        │
   PG(每服务独立库) · Redis · RocketMQ · MinIO · Nacos
```

### 3.2 服务边界（不得越界）

| 服务 | 可拥有的数据 | 禁止 |
|------|--------------|------|
| canvas | 画布图结构、DSL、修订 | 直接改点数、直接调 ComfyUI |
| billing | 账户/流水/冻结/订单 | 直接写画布节点 |
| generation | 任务状态机、模型配置、输出元数据 | 直接改 `point_accounts`（只发 MQ） |
| agent | 会话/消息/动作/Skill/记忆 | 绕过工具白名单改库 |
| asset | 素材元数据与引用 | 绕过预签名直写业务库文件字段 |

### 3.3 关键链路（必须按此实现）

1. **生成扣费**：客户端 → Gateway → billing 冻结（本地事务 + Outbox）→ MQ `generation-task-created` → generation 建任务/执行 → SSE → MQ 结算/解冻。
2. **Agent**：消息 → agent SSE → REST 读 canvas/asset → 规划 → 确认（若需）→ 白名单工具 → 计费链路（若涉及）。
3. **发布**：canvas → gallery 快照 → `pending` → admin 审核 → `published`。

时序细节以技术概要 §1.4 为准。

## 4. 数据 Spec

### 4.1 库划分

`vibepaper_{identity|canvas|asset|generation|billing|agent|enterprise|gallery|admin}`

### 4.2 核心实体与约束

| 实体 | 关键约束 |
|------|----------|
| `point_accounts` | `balance ≥ frozen_points ≥ 0`；扣费行锁 |
| `point_ledgers` | APPEND-ONLY；`UNIQUE(task_id, ledger_type)` |
| `point_reservations` | 与任务冻结一一对应；终态 settled/expired/cancelled |
| `generation_tasks` | 状态机条件 UPDATE；保存 `pricing_version` |
| `canvases` | `version` 乐观锁；归属 `owner_id` |
| `canvas_nodes` / `canvas_edges` | 画布内 ID 唯一；导入重映射 |
| `assets` | 删除前检查 `asset_references` |
| `publications` | 快照不可变；默认 `pending` |

### 4.3 对象存储路径

```
users/{user_id}/uploads/{asset_id}/original
users/{user_id}/assets/{asset_id}/{variant}
tasks/{task_id}/outputs/{output_id}
canvases/{canvas_id}/thumbnails/{version}.webp
skills/{skill_id}/{version}.md
```

上传：预签名直传 → 服务端校验 MIME/大小/哈希 → 异步缩略图。

### 4.4 Redis Key 前缀

`session:` · `agent_ctx:` · `rate:` · `model_health:` · `sse:` · `lock:` · `celery:`  
Redis **不是**权威源，必须可从 PG 重建。

## 5. API Spec（契约骨架）

### 5.1 约定

- Base：`/api/v1`
- 鉴权：Bearer JWT（access 15min / refresh 7d）；注销进黑名单
- 幂等：关键写操作 Header `Idempotency-Key`
- 分页：`page` + `page_size`（或 cursor，按资源在 OpenAPI 固定一种）
- SSE：支持 `Last-Event-ID` 补流；无法补流则返回任务快照

### 5.2 P0 必须具备的资源组

| 组 | 示例路径 | 服务 |
|----|----------|------|
| Auth | `POST /auth/register` · `/auth/login` · `/auth/refresh` · `/auth/logout` | identity |
| Users | `GET /me` · preferences | identity |
| Canvases | `CRUD /canvases` · nodes/edges · import/export | canvas |
| Assets | upload session · CRUD · references | asset |
| Tasks | `POST /tasks` · status · cancel · history | generation + billing 协作 |
| Models | `GET /models`（enabled） | generation |
| Billing | balance · ledgers · recharge（可 mock） | billing |
| Agent | sessions · messages（SSE）· confirm | agent |

完整字段以 OpenAPI 生成物为准；字段名必须落在 PRD §8 数据字典内。

### 5.3 限流（默认）

| 接口 | 阈值 |
|------|------|
| 登录 | 5/min/IP，递增冷却 |
| 注册 | 3/h/IP |
| 提交任务 | 10/min/用户 |
| 画布列表 | 60/min/用户 |
| 节点写 | 120/min/用户+画布 |
| SSE | 5 并发/用户 |
| 全局 | 100 req/s/IP |

Redis 不可用时限流 **Fail Open** 并告警。

## 7. Agent / 生成 Spec

### 7.1 ModelProvider 协议

所有供应商实现：`estimate` · `submit` · `poll` · `cancel` · `healthcheck`。业务禁止依赖供应商私有字段。

### 7.2 工具白名单

| 等级 | 工具 |
|------|------|
| 只读 | `get_canvas_summary` · `get_selected_nodes` · `list_models` · `search_assets` |
| 低风险 | `create_nodes` · `connect_nodes` · `layout_nodes` · `update_node_config` |
| 高风险 | `delete_nodes` · `change_model` · `replace_output` · `submit_generation` |

### 7.3 Celery 队列

`generation_image` · `generation_video` · `generation_audio` · `agent_exec` · `media_processing`

### 7.4 Agent 上下文与记忆实现边界

- **短期记忆**：`agent_messages` 保留会话原始消息，`agent_run_events` 保留权威工具/任务事件；Agent 在每轮运行前按事件序列重建 `agent_session_context` 快照（`context` JSONB），记录画布版本、节点引用、任务终态、待确认动作和未完成步骤。该快照是可从事件重建的检查点，不替代画布或任务真相。
- **上下文压缩**：模型只接收受保护业务事实、结构化会话状态和预算内的最近消息；超过 6000 字符的工具结果只保留头尾预览，并标记原始长度，完整事实必须通过权威工具重新读取。
- **长期记忆**：稳定的用户偏好写入 `user_memories(scope=long_term)`；当前画布规则写入 `user_memories(scope=canvas, canvas_id=...)`。显式“记住/默认/以后都要”指令在 Agent 成功停止后提取并持久化，普通任务输出不自动沉淀。
- **当日记忆与异步更新**：带有“今天/本轮/这次/暂时”等短期限定的指令写入 Redis `agent_daily:{user_id}:{date}`，按 UTC 日过期并限制条数；长期候选可经 `agent_memory_updates` 队列由 Worker 异步确认，Redis 不可用时回退到同步 PG 路径。
- **候选与安全**：`memory_candidates` 先做敏感字段拦截、作用域去重和状态记录，提供待审/接受/拒绝接口；企业作用域仍需管理员授权。记忆写入失败不得把已完成的 Agent 回合标记为失败。
- **未纳入本次基础实现**：语义 Embedding 去重和独立的记忆合并/压缩策略仍按 P2 规划保留，后续可在不改变上述权威边界的前提下接入。

## 8. 权限 Spec（摘要）

角色：`guest` · `user` · `ent_member` · `ent_admin` · `ent_owner` · `ops_admin` · `super_admin`  

未列出的操作默认 **拒绝**。要点：

- 画布写：仅所有者（V1.0）
- 未 `succeeded` 结算的结果不可导出
- 企业管理员默认不可看成员提示词/结果全文（`admin_can_view_content=false`）
- 不可回收 `frozen_points`
- 运营敏感操作：二次确认 + 审计日志

完整矩阵见 PRD §9。
