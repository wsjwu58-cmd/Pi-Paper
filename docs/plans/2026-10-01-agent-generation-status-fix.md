# 桌面 Agent 生成确认和任务状态修复

## 现场证据

2026-10-01 用户报告 Agent 持续显示确认卡片和“排队中”。只读核对本地权威数据库发现：对应图片任务已于 01:25:09 UTC 成功，关联的 Agent task link 仍为 queued；该 run 在接受确认后已提前 completed。另一个视频任务于 01:30:37 UTC 成功。此次修复不得重新提交上述任务。

## 原实现对照与改动

- 原 `src/api/app.ts` 确认后进入 waiting_task，接收任务回调后才结束 run。桌面在原 TypeScript 服务中恢复同样状态关系，并从本地 TaskStore 对账。
- Worker 的快照和事件轮询先读取权威任务状态，再返回持久事件。对账只读任务，禁止重放生成工具。
- Main 对成功结果调用 Local Core 原有摘要校验读接口；结果文件不可读或校验失败时给出明确错误，不能仅凭数据库状态回显成功。
- 原 AgentPanel 在确认 API 返回后关闭卡片；持久 task_status 同样携带确认接受状态，支持重启回放。迟到任务事件不得把已结束的 Agent run 重新标成工作中。
- 控制库升级到 schema 5，任务关联保存 action_id；项目备份和恢复接受该版本。旧 completed run 的遗留 queued 关联只补充任务事件，保持原 run 终态。

## 验证要求

覆盖确认接受、排队、运行、成功、失败、取消、批量全部终结、旧遗留关联和重启幂等；原 Web 页面构建、Agent Worker 构建和运行验证；真实 Key 在隔离本地项目中通过用户自然语言触发一次图片生成并接受确认，校验结果可读，重启后任务数不增加。

既有真实模型验证曾覆盖确认拒绝，未覆盖接受确认后的任务终结链路，不能作为本次缺陷的已验证证据。
