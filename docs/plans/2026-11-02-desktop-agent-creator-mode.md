# Pi-Paper 桌面 Agent 创造模式

2026-11-02 · 设计提案，待评审。适用对象是原画布中的内置 Agent。工程基线为 Pi-Paper 本地工作区 `d3b8a4e` 的市场和 Agent 路径。

## 一次完整的使用

用户在原 Agent 输入框旁选择「创造」，输入“做一个商品三视图插件，分别给正面、侧面和背面写拍摄要求，保存下来，并在当前画布用一次”。

1. Agent 查当前项目可用的市场组件和类似模板。找到完全匹配的版本可以直接复用；需要改已有作品时另存派生包，并保留来源。
2. Agent 编写一个画布模板，包含三组「拍摄要求 → 图片」节点。三个文本节点各连自己的图片节点。宿主在内存中试算，得到 6 个节点、3 条边，校验连线、参数和数量。
3. 校验通过后，Agent 保存「商品三视图」v1.0.0，在当前项目安装并启用模板，按用户要求插入一次。市场页可查看版本和组件，原画布中的六个节点可以继续编辑。
4. Agent 从项目读回结果，再回复“已保存『商品三视图』并插入画布，正面、侧面、背面各有一组拍摄要求和图片节点。尚未生成图片。”用户下次说“再用一次”时，直接选已有版本，追加第二套独立节点。

如果用户只说“帮我做一个可复用插件”，流程停在保存到当前项目市场。如果用户说“只在画布上摆三组节点”，沿用普通创作流程。明确请求“做好并使用”可以连续完成各个低风险动作，活动记录仍分别展示保存、安装、启用和应用。若进一步要求出图，沿用内置 Agent 现有生成确认。

## 范围和交互

- **第一版支持模板和预设。** 模板可以发明新的节点组合、连线与提示词。预设可以为匹配节点提供提示词与已支持的模型参数。模板沿用单组件最多 20 节点的限制，多组件、多次应用按同一请求累计影响。遇到缺少原生能力的请求，明确指出缺少哪项，例如市场的裁剪组件无法实现新的抠图算法。
- **包默认只在当前项目可见。** 在原「插件市场」增加「本项目创作」筛选，沿用原有详情和组件入口。项目内其他会话能发现并复用已启用的作品。跨项目复用通过用户显式导出和导入，公开发布另立流程。普通模式可以用已启用组件，只有创造模式可制作和修订包。
- **会话拥有模式，项目拥有作品。** 新会话和历史无模式字段的会话默认普通模式。用户在原 AgentPanel 切换，Main 持久化并记录模式版本。运行期间切回普通模式或点停止，撤销该轮后续创作写入。会话复制、片段导入和后台续接均不能静默取得创作写权限。
- **权限随动作而定。** 低风险新增在用户任务范围内直接执行。覆盖已有用户字段提供可核对差异和撤销，高风险不可撤销操作走原确认。对外生成继续走原 ApprovalService，安装和应用不会启动生成、上传媒体、配置凭据、创建 MCP 授权或启动本机程序。使用云端文本模型撰写插件时，沿用会话已有的模型发送披露；市场查询只返回必要的结构和选区信息。

以下名称是拟新增的内部命令。工具结果返回结构化字段和可纠正的错误，用户看到插件名、版本、影响及结果。

| 能力 | 输入和返回 | 副作用 |
| --- | --- | --- |
| `inspect` | 查询项目目录、已启用组件、指定组件 schema、限制和示例 | 只读，使用本机目录 |
| `validateDraft` | 接受声明式组件，返回校验后的内容摘要、逐字段诊断、插入数量或拟覆盖字段 | 只试算。草稿修改后重新校验 |
| `saveVersion` | 提交草稿、摘要及基线版本，返回项目内不可变版本 | 新包身份由宿主分配，只能修订本项目来源匹配的版本；同名展示不作为更新依据 |
| `install` / `setEnabled` | 指定包版本、组件和期望状态，返回实际安装快照 | 仅改变当前项目的可用性；对已有组件保留用户选择 |
| `apply` / `getResult` | 绑定已启用组件的版本摘要、目标、画布版本与操作键，返回实际变更及持久状态 | 只应用本次选中的组件；查询结果只读。生成继续使用原工具 |

**现有实现有三处需要先处理。** 一是 `importPackage` 将包放入用户级目录，`saveTemplate` 还会紧接着安装，因此“保存到本项目”需要项目级来源。二是 `installInternal` 对每个新增选中组件设置 `enabled: true`；需要支持创建时原子写入目标启用状态，避免“先启用、再停用”的短暂生效。三是模板插入目前带有 Renderer 的节点视图、回调与保存合并逻辑。Agent 应共用纯数据转换与权威画布命令，不能通过模拟点击或重新实现一套连线规则消费插件。

## 数据、并发和恢复

1. **包与版本。** 保留可移植 manifest v1，新增项目市场状态格式，记录来源、包标识、不可变版本、规范化清单摘要及父版本。Main 写入来源信息，模型提供的 `author` 仅用于显示。与内置、在线、手工导入的包标识冲突时拒绝覆盖。现有项目的安装快照、启停选择和回退版本要经带备份的可重复迁移保留。项目移动及备份恢复以后仍按稳定 ID 解析。
2. **作用域。** Main 从活动会话绑定解析项目、画布和模式，不接受模型自报路径或权限。普通模式、外部 MCP、旧运行和跨项目调用不能取得制作工具。请求仅接受允许的组件和字段；禁止代码、可执行文件、安装钩子、网络地址和秘密字段，包内文本不能授予工具权限。首期无需把媒体二进制或历史对话写进包。
3. **冲突。** 预览绑定版本摘要、选区及画布版本。应用前协调原画布未保存编辑，版本或目标已变就返回新差异。操作按需重新试算，不以旧整图覆盖。校验分层进行，包可移植性在保存时检查，当前目标和启用模型支持的参数在应用时再检查。
4. **恢复。** 每个写步骤使用宿主分配的稳定操作键和输入摘要。项目存储原子保存包与对应写入标记；画布变更通过现有幂等命令提交并关联同一操作键，SQLite 记录步骤与结果引用。响应丢失或重启时先从项目和画布权威状态对账。能证实已应用才回报成功；不能判定时标记待核对并停止重放。用户主动“再插一次”才创建新的操作键。
5. **部分成功。** 已保存的包在安装或应用失败后仍可查看。比如显示“插件已保存并启用；画布在预览后发生编辑，尚未插入”。同一版本重试只补未完成步骤。停用、卸载、升级和版本回退保留用户已编辑的节点、素材和历史任务。

## 节点也进入市场

当前画布有文本、图片、视频、音频、合成和导演台六类原生节点。工具栏创建菜单和 React Flow 视图分别维护固定映射，项目存储在创建、连线和导入时按同一组六类校验。现有市场模板可以组合这些节点。要让用户选装新节点，应让市场描述一个可创建的节点，并为每个实例保留可移植的定义。

| 用户可选的内容 | 如何创建和运行 |
| --- | --- |
| 基础节点 | 市场「节点」分类列出六种随包能力，默认保留原创建入口。用户可调整常用菜单；隐藏某项只影响新建入口，已有节点仍可编辑。 |
| 自定义单节点 | 新增声明式组件 `node_definition`。用户或创造模式 Agent 选择基础类型，定义名称、字段、默认值及其到宿主参数的映射。例如「商品棚拍图」基于图片节点，提供商品卖点、背景和光线字段，生成前可查看拼出的提示词。 |
| 多节点工作流 | 如「商品三视图」会产生三组可编辑节点，仍按模板插入。菜单展示将插入的节点数量，用户能区分一个专用节点和一组工作流。 |

**用户路径。** 在原插件市场按「节点」筛选，可预览字段、输入输出、适用模型，再决定将哪些节点加入本项目。原画布的新增菜单按「基础」「本项目」显示可创建项，空画布入口、工具栏、上下文菜单和 Agent 查询共用目录；从连接端拉出菜单时按实际端口筛选。用户也可在原市场选择基础类型、配置字段、预览并保存，或在创造模式中用自然语言完成相同操作。选择节点和填写字段只创建可编辑实例。

**第一版定义边界。** 在基础编辑器中增加宿主渲染的文本、数字、枚举等受限控件。字段只允许绑定宿主认可的参数、占位文本或更窄的取值集合；端口继承原生媒体语义。映射只允许有界替换，不解释脚本或表达式。Main 在保存定义、创建实例、连线和任务提交时各自验证相应约束。自定义新媒体类型、新算法、独立编辑器或后台处理器，需要另行交付宿主实现，已安装插件不能注册可执行代码。

**实例兼容。** 项目内继续持久化基础 `node.type`，另存 `definitionRef`（包、组件、版本、摘要）、字段值及编辑所需定义快照。TaskStore 只接收宿主解析并按模型能力校验后的参数。旧节点缺少扩展字段时照常打开。项目备份、画布导出导入和复制保留快照；卸载后隐藏新的创建入口，旧实例仍能按快照编辑。升级默认影响新建节点；迁移已有节点需预览字段差异，不能改写历史任务。MCP 仍受原授权约束，未知定义或超出权限的操作由 Main 拒绝。

## 将系统 Skill 纳入统一目录

**当前状态。** [生成清单](../../pi-main/packages/vibepaper-agent-service/src/domain/skill-manifest.generated.ts)包含 23 个系统 Skill，其中 21 个为动态 Skill，2 个为核心 Skill（Canvas Cookbook、DirectorStage 3D 导演台）。[桌面 Skill 上下文](../../pi-main/packages/vibepaper-agent-service/src/desktop/skill-context.ts)直接读取系统清单。另一条路径由[项目 Skill 加载器](../../pi-paper-desktop/src/project-agent-skills.cjs)将项目文件与已安装的市场 Skill 合并。随包的「商品棚拍策划」及仓库在线目录中的「分镜创作简报」都是市场支持 Skill 的例子。现状是 Agent 能消费多种来源，市场尚未管理原有 23 项。

**建议分两步交付。**

1. 先将 23 个系统条目映射到市场「官方 Skill」，仍从同一清单生成目录和正文。2 个核心 Skill 标注「系统必需」，可查看用途，保留宿主提供的可用性。21 个动态 Skill 按用途分组展示。项目自建 Skill 保留原文件和编辑入口，并在同一目录标注来源。
2. 再把 21 个动态 Skill 的项目启停接入统一解析器。已有项目升级时默认保留原可用集合；新项目提供兼容默认和按项调整。原 Skill 选择器、Agent 可发现索引、显式加载、历史会话恢复和市场详情使用同一稳定 key。市场通用 Skill 当前使用按包和组件派生的 `market-…` ID，官方迁移必须保留旧 key 或提供显式别名。修改桌面上下文中直接遍历全部 `SYSTEM_SKILLS` 的路径，让停用对后续加载生效。已有转录、内容摘要和会话快照可追溯。工具权限与生成确认继续由宿主执行。

用户可以安装一个含「商品棚拍图」节点、「柔光」预设和「商品棚拍策划」Skill 的组合包，也可以只选节点。创建节点所需的字段和参数映射必须自包含；可选 Skill 只帮助 Agent 使用它。

## 实施次序和验收

**第一步跑通模板。** 更新桌面契约、接口和数据字典，接入会话模式、项目级来源、能力查询、保存与消费。用上面的三视图自然语言用例，在同一会话内从空项目完成创建和应用。重启后换一个会话复用该版本。

**第二步补齐预设、修订和恢复。** 在选中图片节点应用模板包附带的预设，验证模型参数、差异与撤销。将 v1.0.0 修订为新版本并回退，分别检查已有节点、新插入节点和用户手工修改的内容。测试停止、两会话竞争、响应丢失、版本冲突、备份还原和项目切换。

**第三步扩展组件。** 按实际消费端逐类开放导演场景、机位、运镜、海报布局和选区命令。项目 Skill 单独接入既有 Skill 选择、快照和停用逻辑；新增文本只能在既有工具白名单内发挥作用。每类先完成从自然语言创作到实际编辑器结果的验收，再加入面向模型的能力目录。

**节点和 Skill 的落地顺序。** 第一步即可从现有清单生成官方 Skill 浏览目录，并为六类节点统一发现入口。第二步在模板验证通过后优先做一个「商品棚拍图」单节点，验证手动定义、Agent 制作、按项目选装、原画布创建和本地恢复。之后开放其他受支持的字段映射，并完成动态 Skill 的实际启停迁移。

| 发布验收场景 | 可观测结果 |
| --- | --- |
| 只创建；创建并使用；再次主动使用 | 分别为画布新增 0、6、6 个节点。每次新插入只有本组 3 条边；同一请求重放新增 0 个。全过程生成任务增量为 0。 |
| 切模式、切项目、外部 MCP 尝试写、包携带脚本 | Main 拒绝越界写入；项目与目录保持原状态。 |
| 画布存在未保存编辑，或写入后未收到回执 | 用户编辑保留；能查出哪一步成功；重启不重复插入。 |
| 停用并卸载、升级并回退 | 市场显示真实版本和启用状态；已应用的节点与后续手工修改保留。 |
| 手动与 Agent 各创建一个同版本棚拍图节点 | 两条入口生成相同定义摘要、等价字段与图片端口。断开网络可编辑，卸载后旧实例可打开、可移植，新建菜单移除对应项。 |
| 升级已有项目，在市场停用一个动态官方 Skill | 23 个官方条目按原 key 唯一出现，核心 2 项持续可用，停用项不再进入后续可用索引和加载结果，旧会话记录与快照可查询。 |
| 用户要求实际生成 | 原节点展示确认后的任务和结果；拒绝、过期、重启均不新增付费任务。协议测试与真实供应商结果分别记录。 |

## 从创造模式扩展到整个工作台

### 先让产品共用一份能力目录

现有[画布插件面板](../../pi-paper-web/src/features/canvas/CanvasPlugins.tsx)按组件类型筛选、决定按钮名称，[画布页](../../pi-paper-web/src/features/canvas/CanvasPage.tsx)的 `usePluginComponent` 又按类型选择处理过程。举例说，已有的「分镜导出」若要从选区菜单和 Agent 同时使用，两端都需要知道可选字段、选区要求和导出行为。继续加组件会让相同条件散落到更多入口。这是优先级最高的改造点。

可借鉴 Harness 的只读能力发现，以及 Pi 的类型化注册和资源诊断。仓库内的 [Pi ResourceLoader](../../pi-main/packages/coding-agent/src/core/resource-loader.ts)按类型列举 Skill、提示模板和主题，返回诊断，并支持重载；[Pi ExtensionAPI](../../pi-main/packages/coding-agent/src/core/extensions/types.ts)分别注册工具、命令和提供方。[Harness 工具源码](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/extensions/tool-cordis/src/index.ts)展示了先列目录再查询实际 schema 的方式。Pi-Paper 可以使用这些设计，也可以继续使用自己的声明式包格式。

建议给每种能力定义稳定标识、契约版本、输入输出、可用位置、来源和效果。**宿主注册实际处理器**，提供实现、校验及允许使用的入口；**创作包引用处理器**，提供字段、版式、默认值和组合步骤。市场回答“装了什么”，项目解析器回答“现在能用什么、为何不能用”，Main 在执行时按调用者重新判断权限。角色、选区、模型缺失或类型不兼容都能返回具体原因。普通包无权声明处理器地址、执行路径或降低风险等级。现有 v1 包可由读取适配器映射，避免要求用户重装。

### 值得开放的扩展点

| 优先级 | 扩展点 | 用户能做什么 | 实施锚点与边界 |
| --- | --- | --- | --- |
| P0 | 原菜单、命令与编辑器字段 | 同一个「导出分镜」出现在适合的选区菜单，Agent 也能向用户提供相同导出预览 | 从原画布提取具名命令；位置限于宿主声明的节点菜单、选区、工具栏、检查器等。插件提供标题、输入绑定和受限谓词，宿主渲染界面和处理文件选择。 |
| P1 | 创作流程配方 | 把镜头排序、检查缺少的提示词、准备分镜表保存成可反复执行的操作 | 模板决定插入的节点和连线；配方编排用户主动触发的操作。首期支持有限顺序、类型化引用、运行前预览和逐步结果。复用[桌面计划执行服务](../../pi-main/packages/vibepaper-agent-service/src/desktop/plan-execution-service.ts)及原命令，不引入第二个调度器。遇到生成步骤必须进入原确认。 |
| P1 | Agent 角色与上下文选择 | 在同一项目选择「分镜导演」或「审片员」；前者组织镜头，后者检查选区并列出问题 | 角色可组合已启用 Skill、提示模板、允许的工具子集和上下文片段种类。实际工具取宿主角色权限交集；准入规则和上下文预算继续由宿主负责。只加载必要内容。角色、用户选择的创造模式和会话模型绑定分别记录。[现有角色选择](../../pi-main/packages/vibepaper-agent-service/src/application/profile-selector.ts) |
| P1 | 导出格式与只读作品检查 | 同一组选中镜头可以导出给剪辑师的分镜表，也可在交付前检查漏镜号、缺参考图、缺提示词 | 首期配置既有输出格式的字段、排序与必填规则。检查返回可定位的问题，由用户选择是否修复。将来可增加新的宿主导出器。包不指定目标绝对路径。 |
| P2 | 媒体处理、模型与提供方适配 | 同一个节点按输入模态、参考图和分辨率要求列出已配置的兼容绑定；预设能说明某个参数为什么不可用 | 面向市场开放能力要求和参数映射。新增处理算法、厂商协议、鉴权或请求转换由随应用交付的受信实现注册。[Pi 官方适配入口](../../pi-main/packages/ai/src/media/index.ts)及[能力目录](../../pi-main/packages/ai/src/media/catalog.ts)已可复用。模型由用户选择，任务持久化其绑定及参数快照。 |

这几层可以装在同一个「短剧工作包」里。用户只选装分镜导出时，无需同时安装导演角色或配置模型。依赖第一版只采用**宿主能力标识与兼容版本、包内明确引用**；安装前可预检并列出缺项。待实际出现跨包复用需求时再设计版本解析。

### 开发者和 Agent 如何验证插件

在既有插件详情及创造模式试算结果里提供同一份本地检查报告，包括实际来源与版本、可用入口、缺失依赖、同名冲突、被禁用原因，以及针对样例输入的预览。目录变更后刷新新操作；正在执行的步骤保留其版本快照，停用禁止后续启动。标识冲突不能默默覆盖。升级、停用与卸载分别检验已应用节点、历史会话和在途任务。用户选用云端文本模型时沿用会话披露，本地检查本身可离线运行。

**推荐试点为现有「分镜导出」。** 给它注册一个宿主处理器，分别从选区菜单和内置 Agent 对同一组选中节点请求预览。两端应返回相同列、排序、记录及缺失字段提示；用户选择位置后才写文件。停用组件后两端都失去该组件入口，已导出的文件和原画布仍然可读。验收时在无模型凭据环境跑本地预览及导出契约，用已配置文本模型另测真实 Agent 对话。再用已有「选区排列」验证写画布时的撤销、版本冲突和恢复。两个试点通过后，按相同接口添加「商品棚拍图」节点与导演角色，检验能否只增加定义和必要的处理器，避免反复修改原画布页的分支。

画布和任务存储、版本冲突处理、幂等与恢复、凭据、MCP 授权、云端发送范围及生成确认由宿主持有。将来若确需加载第三方可执行算法，应单独立项定义进程隔离、权限、资源预算与崩溃恢复，再调整产品契约。
