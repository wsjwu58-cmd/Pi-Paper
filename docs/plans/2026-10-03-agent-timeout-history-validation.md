# Agent 请求超时与重复用户消息修复

## 现场原因

最新本地会话的原始模型终止原因是 `Request timed out.`。桌面运行时此前将供应商超时归入 `MODEL_UNAVAILABLE`，使界面误提示服务配置问题。发送成功后，历史刷新可能先写入用户消息，随后乐观消息再次追加，造成同一次 Run 的用户消息重复。

## 修改

- 在原 Agent TypeScript 运行时区分供应商请求超时，桌面返回 `MODEL_TIMEOUT`；原 Web 错误语义保持不变。
- 在原前端控制器插入乐观用户消息时按 Run 合并；历史恢复也合并同一个 Run 的重复用户消息。不同 Run 的相同文本继续分别保留，未关联 Run 的历史不按文本强行删除。
- 不自动重放失败请求或画布写操作；供应商可用性仍需后续真实调用确认。

## 验证

- Agent 运行时定向测试：24 项通过，覆盖供应商超时及原 Web 映射。
- 前端事件与历史测试：31 项通过，覆盖历史先到达、同 Run 重复与不同 Run 相同文本。
- Pi 完整工程检查、前端构建、桌面 Worker 构建及跨重启 Skill/片段验证通过。
- 本次未发起收费模型调用，不能据此宣称供应商超时已经消失。
