# Agent 续跑、可观测性与意图分流改造

## 目标

本改造解决生成工作流在异步任务结束后停止、确认卡覆盖既有对话、执行过程不可追溯，以及可恢复工具故障没有统一重试策略的问题。适用范围为 `agent-service` 的 Pi Run、任务终态回调与前端 Agent 对话面板。

## 交付行为

### 1. 任务终态屏障与续跑

- 每个确认并提交的生成工作流都以原始 Agent Run 为边界续跑，而不是以某一个任务为边界。
- 每个生成任务回调先落库；只要同一 Run 内仍有 `running` 或 `compensation_required` 的批量任务，就保持 `waiting_task`，不启动下一轮。
- 最后一个任务进入终态（`succeeded`、`failed`、`cancelled` 或 `expired`）后，使用 `task-continuation:{runId}` 启动至多一个后续 Run。因此多个回调并发、重复投递时不会重复续跑。
- 全部成功时，续跑读取最新画布并继续尚未完成的非重复步骤。
- 有任何失败时，续跑读取画布，保留成功产物，说明失败影响和可恢复下一步；不会自动新建收费任务，也不会执行依赖失败产物的下游步骤。重新收费生成仍必须走新的确认。

这与任务状态机保持一致：只有 Generation 的终态通知才会打开屏障；点数结算、失败解冻仍由 Generation/Billing 的既有事务链路负责。

### 2. 确认卡的对话布局

- 待确认操作只显示在对话滚动区顶部的紧凑卡片中，不再嵌入或替换历史助手消息。
- 卡片采用对话面板既有的表面色、边框和强调色，展示操作摘要、待生成数量、预计点数和原因。
- 用户确认、取消、失效或提交完成后，卡片从顶部待办区移除；原始对话与执行记录保留。

### 3. Agent 执行记录

SSE 事件新增并持久化以下可展开执行记录：

- `thinking`：提供方输出的 Agent 思考块；
- `tool_started` / `tool_completed`：工具调用参数与结果；
- `tool_retry`：重试次数、上限和错误码；
- `confirmation_required`、`task_status` 与 Run 终态。

前端按 Run 将事件归属到固定的助手消息。续跑会新建自己的消息，而不会把前一轮的对话文本或执行过程覆盖。展示原始载荷前会递归隐藏密钥、授权头、令牌及画布/会话/任务/节点内部标识；单条内容限制为 6000 字符，用户可在执行记录中展开查看。

会话历史接口同时返回该会话已持久化的 Run 事件。页面刷新时，前端先恢复消息正文，再按事件序号回放思考、工具、重试和任务状态；新写入的助手消息带有内部 Run 关联，仅用于将轨迹归并回正确消息，不对用户展示。

### 4. 工具失败重试

所有运行时工具经统一包装器执行。满足下列任一条件时才自动重试，最多三次（即最多两次重试）：

- HTTP `408`、`429`、`5xx`；
- `MODEL_TIMEOUT`、`MODEL_UNAVAILABLE`、`CANVAS_UNAVAILABLE`、`DOWNSTREAM_UNAVAILABLE`。

延迟采用 250ms、500ms 的指数退避并加入小幅随机抖动，且会响应用户中止。`INVALID_INPUT`、`PERMISSION_DENIED`、`VERSION_CONFLICT`、`INSUFFICIENT_POINTS`、内容拦截、成本上限与资源不存在均立即失败，避免重复写入或重复扣费。每次重试经 Pi 工具更新事件实时写入对话执行记录。

### 5. 意图分流阶段

路由现在向 LLM 主回合注入显式阶段约束：

1. **确定性阶段**：画布统计、明确写节点、生成和多步骤创作等高置信模式直接给出安全的首步约束；
2. **语义阶段**：低置信的开放请求由 LLM 结合画布、选择节点和 Skill 上下文判断，但在调用工具前必须核验目标、引用关系、费用及缺失信息；
3. **澄清阶段**：引用对象不明确时，只允许提出自然语言澄清问题，禁止写画布、提交生成或触发计费工具。

这不是把安全判断完全交给模型：确定性规则仍是费用、确认和工具白名单的前置护栏，LLM 只在语义阶段做受约束的理解与规划。

## 验收场景

1. 两个关键帧任务分别成功和失败：最后一个任务到达终态前不续跑；到达后只创建一条恢复 Run，并不自动提交视频生成。
2. 两个任务都成功：最后一个终态回调后继续创建并连接后续步骤，重复回调不会额外创建 Run。
3. 确认待办出现时，之前助手消息、思考步骤和工具结果仍可滚动查看；确认或取消后卡片消失。
4. Agent 返回思考块、加载 Skill、调用工具和工具重试时，对话执行记录按顺序展示相应条目，敏感字段不可见。
5. 工具在两次 `MODEL_TIMEOUT` 后成功，调用三次并显示两条重试；`VERSION_CONFLICT` 只调用一次并要求刷新/重试。
6. “处理刚才那个”只触发澄清；明确的“生成三张关键帧并连接”进入计划与确认路径。
