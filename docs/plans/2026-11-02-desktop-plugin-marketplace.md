# Pi-Paper 桌面插件市场设计

2026-11-02 · 产品与工程方案。本文的验收条件描述交付目标，实际通过范围以验证记录为准。

## 用户体验

工作区侧栏中的「插件市场」供用户发现、安装、配置和管理创作包。可以先看一个包能创作什么，再选择需要的组件。进入项目后，组件出现在适用的创作位置。用户移除插件后仍能重新打开和编辑已有作品。

首个样例是「商品棚拍」。用户查看内容与用途，选择画布模板、棚拍参考素材、生成预设或商品创作 Skill。安装后在原画布插入模板，替换参考、调整提示词，在已配置模型支持的范围内选参数，必要时显式发起生成。用户可以把修改过的结构导出，在另一项目重新使用。

市场页提供搜索、详情、已安装管理和本地文件导入。详情须说明来源、版本、组件、使用入口和限制。允许无活动项目时浏览。写入前明确选择目标项目。组合包中任何组件能独立安装才允许独立勾选；组件引用其他资源时应内含所需数据或明确其依赖。

## 类型和阶段

| 类型 | 可配置内容及使用位置 | 实施顺序 |
| --- | --- | --- |
| 画布模板与工作流 | 通过现有节点及连线表达可编辑拓扑。用户在画布中插入、修改或另存 | 首期 |
| 素材与风格包 | 把可检查的本地素材添加到当前项目，供用户替换或引用 | 首期，格式按已实现解码能力开放 |
| 提示词与生成预设 | 在匹配节点应用提示词和参数；用户选择模型并检查生效值 | 首期 |
| Agent Skill 与选区命令 | 项目 Skill 进入现有面板和选择器；命令需要相应选区与工具能力 | 首期支持 Skill，后续支持新命令 |
| 导演场景、机位、运镜 | 导演舞台读取结构化场景和镜头，用户替换商品、角色、机位 | 第二期，优先于通用代码扩展 |
| 设计模板与媒体工具 | 版式在设计入口使用，媒体工具出现在选中对象的菜单中 | 对应桌面编辑器及处理能力就绪后 |
| 导入导出及外部工具 | 分镜表、交付格式、经用户配置的本地处理程序 | 后续，另定权限及运行协议 |

参考站实测在同一项目切换 Canvas、Design、Director、Work，验证了模板应用、图片工具菜单和场景对象选择。它为产品交互提供参考，各类型能否在桌面市场安装以本机实际消费能力为准。[参考项目](https://vibepaper.io/workspace?lang=en)

## 来源、安装与配置

目录包含随应用发行的包、可移植的本地 JSON 文件和用户主动刷新的在线条目。在无账号、无网络时仍可浏览和使用已缓存、已导入的资源。在线目录固定来自公开仓库 `wsjwu58-cmd/Pi-Paper` 的 `feat/desktop-local-migration` 分支：刷新先解析分支当前提交，再从该提交读取目录；下载所选文件时沿用同一提交，并校验声明的字节数、SHA-256、内容元数据和应用版本及组件类型。网络失败不覆盖已有缓存，未知类型只禁用对应条目。摘要保证内容与该提交中的目录一致，不是发布者签名。导入只保存到本地目录，组件安装、启用和应用仍为独立动作。支持本地及在线独立 Pi `SKILL.md` 的名称、说明和指令导入；辅助文件、脚本、安装钩子、npm 包及无法保留语义的权限或兼容性配置不导入，常见依赖引用会拒绝，用户应预览指令。第三方代码扩展需要独立的执行隔离方案。

包标识与组件标识须稳定，包携带格式版本与发布版本。安装记录关联项目、包版本、所选组件及启用状态。相同版本的重装不能产生重复组件。只有兼容的更新才可替换已安装版本，保留可回退版本。用户保存的模板是独立副本。个人默认、项目覆盖和节点单次修改属于三个不同作用域；首期优先项目安装和节点编辑，跨项目复用通过文件实现。

安装产生的是可用资源，应用才创建项目内容。再次主动插入模板是一次新的创作操作，应生成新节点 ID，只重映射模板内明确声明的边。停用或卸载后隐藏未来入口，保留已插入节点、项目素材、历史会话与任务。修改安装选择、更新及回退都须遵守这个规则。包格式不承载 Key、项目绝对路径、历史任务、会话、原始节点身份或运行权限。

## 实现边界

**包格式 v1。** 同一清单可来自内置目录或本地文件。包级字段包括 `schemaVersion`、`id`、`version`、`name`、`description`、`author`、`components`。每个组件有独立的 `id`、`type`、`name`、`description` 和 `data`。以下是可导入的最小图片提示词包，用户可以用它验证从文件导入、安装和应用到选中图片节点的路径。

```json
{
  "schemaVersion": 1,
  "id": "my-product-lighting",
  "version": "1.0.0",
  "name": "我的商品布光",
  "description": "用于商品主图的提示词",
  "author": "本地创作者",
  "components": [
    {
      "id": "soft-side-light",
      "type": "preset",
      "name": "柔和侧光",
      "description": "在图片节点应用侧光拍摄要求",
      "data": {
        "nodeType": "image",
        "params": { "prompt": "用柔和的侧光突出商品纹理，保留原有颜色和商标。" }
      }
    }
  ]
}
```

模板的 `data.nodes` 存包内临时名称、类型、坐标和可移植参数，`data.edges` 按包内名称引用两端。图片素材的 `data` 包含 `kind`、`mime` 和 Base64 编码的 PNG 内容。Skill 的 `data` 包含 `category` 与 `instructions`。包发布版本与项目内 Skill 编辑版本分别管理。个人模板仅包含用户选中节点的可移植字段与内部连线。

- Electron Main 负责验证调用来源、当前项目、文件选择与包内容；导入校验格式版本、类型、大小、唯一性、引用和字段白名单。持久化采用版本化格式和原子替换，更新失败保留原可用状态。Renderer 只使用具名 preload 方法。
- 市场页沿用原工作区导航。消费端接在原 Canvas、节点编辑器和 Agent Skill 链路，复用当前项目的保存、版本冲突和刷新机制。模板中的引用不授予文件、媒体或模型访问权限。
- 预设应用前按节点及当前模型能力校验。缺少兼容模型时给出可操作提示；须由用户选择有效绑定。生成、费用披露、外部 Agent 确认、幂等及结果落盘均沿用原任务链路。
- 创作包可以包含描述性文字，不能提供可执行代码或安装阶段副作用。第三方说明属于项目内容，不覆盖原 Agent 工具白名单及用户确认策略。

## 验收场景

1. 从原工作区进入市场，预览棚拍样例。无项目可浏览，有项目后只安装模板与素材，未选预设和 Skill 不出现在对应入口。
2. 插入模板两次，验证节点各自独立、边只连接本次节点。更改后重开项目，节点、所用素材与连线可读。再次打开另一项目时不沿用前一项目的启用状态。
3. 在匹配节点应用预设，核对实际生效参数。没有配置模型或参数不兼容时显示原因。浏览、安装、应用都不会新增生成任务。
4. 在原 Skill 面板选择安装的 Skill，停用后不能在新请求中选择。测试安装、更新、回退、重启和卸载，保证用户作品及独立编辑副本可读。
5. 导出可移植模板，从另一个项目导入。未知格式、超限文件、重复 ID、越界路径和无效连线失败时不留下可用的半包。测试导入取消、磁盘写失败及旧项目首次使用。
6. 记录源码测试、开发壳实测、正式安装包验收三层证据。远程目录、真实供应商生成、导演和设计类操作分别验收。

## 后续交付契约（2026-11-02）

| 用户操作 | 生效范围与结果 |
| --- | --- |
| 刷新官方目录、下载资源 | 刷新解析默认分支提交并校验索引，下载绑定所见提交和摘要。下载成功后先预览，再按组件安装。提供可独立使用的 Pi Markdown Skill 导入。 |
| 配置生成预设 | 同一包版本的字段按包默认、个人默认、项目覆盖依次合并。清空字段表示继承下层。节点只在用户应用预设时改变，导出原包不附带私人设置。 |
| 在导演台使用创作包 | 导入可编辑的舞台对象、机位或起止镜头，允许调整和预览。场景对象采用本项目的新身份。 |
| 从源图制作海报或裁剪图片 | 调整海报尺寸、图片位置、标题样式，保存为普通项目 PNG。源图保留编辑入口。裁剪组件在原图片编辑器工作。 |
| 对选区执行操作或交付分镜 | 通过声明式命令排列选中节点；分镜表支持选取字段、调整顺序及 CSV 导出，用户填写的文本作为数据单元格。运镜列保留文本运镜，导演节点的结构化机位以本地化角度和距离展示，运镜包含起点、终点及时长；格式无效时明确标注。 |
| 为外部 Agent 配置画布连接 | 市场显示建议范围，跳转到现有 MCP 设置页，由用户编辑并创建实际授权。安装、启停与卸载市场模板不会创建或撤销独立的授权。 |
| 桌面调用本地文本工具 | 项目启用连接器后，用户选择本地程序，检查可用工具并选择其一。显式运行前展示待发送文本，输出作为文本查看或保存。配置保存在本机，包不携带可执行文件、访问令牌或命令行。 |

跨平台验证在安装载荷内重跑同一条工作区、市场与画布操作路径。发布索引与包必须同时提交，先用公开源验证固定提交的下载，再在隔离用户目录中验证应用操作。真实模型、安装向导、签名和生成的计费结果分别记证据。
