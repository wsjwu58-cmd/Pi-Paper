# 2026-10-02 持久计划执行接通

## 执行边界

沿用原 `PlanCompiler`、依赖/步骤状态、只读调度器、`ReadTools`、`createRuntimeTools`、`CanvasCommandService`、生成/删除确认与受限 Tool Gateway。在原 Agent TypeScript 中补齐确认感知的本地计划协调器；Worker 只提供进程路由、Gateway 和权威任务读取，原前端 API 本地适配经 Preload/Main 调用。

| 本地接口 | 行为 |
| --- | --- |
| `POST /agent/plans/{id}/execute` | 显式传入原四类 profile 之一；绑定当前项目、会话、画布与创建时的执行范围。按依赖推进已准备步骤，生成/删除停在原确认卡。 |
| `GET /agent/plans/{id}/execution` | 只读取持久执行状态；读取历史不派发工具。 |
| `POST /agent/plans/{id}/cancel` | 持久停止计划后续步骤、失效未消费确认；已获准提交的任务仍按权威状态对账。 |
| 原确认与任务同步接口 | 确认后沿原幂等任务键提交，任务终态核验输出后继续依赖步骤。计划续跑与普通 Pi 续跑只有一个执行方。 |

原四个计划 create/get/ready-set/rerun 接口继续保留。创建只编译与保存，执行需要显式请求；不新增独立任务抽屉或平行 Agent 页面。原 Pi 自然语言运行尚无“编制并执行持久计划”的工具或调用方，因此此次接通不把普通工具调用伪报为自动建计划。原计划参数仍是固定输入，没有新增步骤输出变量或模板语言。

## 状态与恢复

控制库升级到 v8，升级前保留经过校验的原库快照。

| 表 | 用途 |
| --- | --- |
| `desktop_plan_execution_context` | 计划画布、profile 和持久停止标记；新计划冻结绑定，旧 v7 计划首次显式执行才冻结经过完整编译验证的绑定。 |
| `desktop_plan_executions` | 步骤与 Run、确认动作关联及 `running/waiting_confirmation/waiting_task/completed/failed/cancelled/reconciliation_required` 状态。 |
| `desktop_plan_execution_tasks` | 整批任务关联、权威终态与核验过的输出引用；任一任务失败阻断依赖，全部任务成功且输出可读取才完成步骤。 |

步骤调用原工具 schema 校验，画布写入沿原版本 CAS 和操作幂等账本。原 Gateway 对不确定操作查询幂等结果；计划重启时未完成的普通画布写步骤进入待核验，不自动重放。生成确认消费后恢复使用同一确认动作与任务幂等键核验或修复任务关联，不创建新的确认。普通 Pi 任务续跑从持久计划 Run 关联识别所属执行方。

关闭进程只停止本实例派发并等待正在执行的操作，不撤销已获准任务；再次打开后读取本地 Run、确认、操作和 TaskStore 状态。用户停止、会话归档或删除会持久阻断后续执行。恢复备份副本保留计划历史，但停止标记置位、活动执行取消、授权失效；副本不会继承源项目的自动执行权。

批量生成逐个记录已提交任务的关联。取消发生在某个请求执行中时，该请求返回的已创建任务仍保留关联，其后的请求不再派发；后续对账只更新这些任务的真实结果。重复确认不创建重复任务，也不把已完成步骤降回等待状态。会话已有运行回合时，计划执行不能先占用步骤再因 Run 冲突遗留空执行记录。
