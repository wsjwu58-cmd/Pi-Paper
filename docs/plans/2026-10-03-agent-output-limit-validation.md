# Agent 输出截断与中断反馈修复

## 现场证据

2026-10-03 只读检查本地会话及 Run 记录：猫鼠短剧回合最后一次模型回复的 `stopReason` 为 `length`，只有 thinking 内容，没有正文或工具调用。Worker 因正文为空将其记为 `AGENT_MODEL_REQUEST_FAILED`，界面只弹出临时通用错误，无法说明中断原因。另一新会话的确认后续跑返回 `Connection error.`，属于独立的模型连接中断。

已产生的节点、连线、任务和媒体仍由本地权威存储保留；本次修复不删除或改写用户项目及旧会话记录。

## 修复边界

- 在原 TypeScript Agent runtime 中识别输出截断，保留同轮 Pi 消息及工具结果，进行有限续跑；不重放已完成的写工具。
- 生成确认和用户停止优先于自动续跑；整体超时及续跑次数均有上限。
- 截断续跑仍失败使用 `AGENT_MODEL_OUTPUT_LIMIT`；模型连接中断使用 `AGENT_MODEL_CONNECTION_FAILED`。不将输出截断归因于 API Key。
- 原 AgentPanel 在对应回合持久显示中断原因，历史重开后依旧可见；没有正文的失败回合也不被过滤。
- 只读历史恢复不自动派发新的工具或云端生成。旧失败回合可由用户发送“继续”接着处理。
